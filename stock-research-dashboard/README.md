# Stockwise — Stock Research Dashboard

A beginner-friendly website for exploring a company, understanding its financial information and news, and writing your own research summary.

## Try it locally

You need Node.js 22.13 or newer and npm.

1. Open a terminal in this `stock-research-dashboard` folder.
2. Install the packages with `npm install`.
3. Build the website with `npm run build`.
4. Set up the local database with `npm run setup:data`. This applies only pending migrations and can be run again after updates.
5. For local admin controls, create an ignored `.dev.vars` file containing `STOCKWISE_ADMIN_USER_IDS=local_seedy`. This is the development preview identity, not a hosted login.
6. Start the website with `npm run dev`.
7. Open the local address printed in the terminal. Click **Sign in** on Data Library to activate the supplied local preview account.

No API keys are required to explore the sample workspace or use uploaded CSV/JSON data. File uploads need the local database setup above; the hosted site provisions persistent database and file storage through Sites.

## What you can do

- Search the sample companies by name or ticker: Apple (AAPL), Microsoft (MSFT), NVIDIA (NVDA), Tesla (TSLA), and Alphabet (GOOGL).
- View a company description, a stock price, daily change, and an interactive historical chart.
- Change the chart period or hover over the line to inspect a closing price.
- Explore revenue, net profit, assets, liabilities, and plain-English definitions.
- Read news headlines and open the source links.
- Explore a clearly labelled sample explanation, or generate AI summaries after connecting services.
- Add and remove companies from your watchlist.
- Write your own summary. Notes save automatically in this browser and appear under Research notes.
- Download a summary as a Markdown text file.
- Open **Finance academy** for all 12 stages and 165 terms from the supplied learning map, including formulas and interactive calculators.
- Open **Data library** to upload historical CSV/JSON data, preview rows, view charts and formula-based metrics, attach reports, and save source websites.
- Link new files to earlier versions without overwriting history.
- Use **Administration** to manage existing users’ roles, shared company files, and recorded file activity.

Use Command/Ctrl + K or `/` to focus company search. Press Escape to dismiss search or an information dialog.

## Sample mode

All sample prices, financial figures, chart points, and news stories are fictional teaching examples. They are not current market data. Sample headline links lead to the relevant company's newsroom, not an article matching the fictional headline. Sample explanations are written examples, not generated by an AI model.

Your notes and watchlist use browser storage separately for each signed-in account. They do not sync across devices. Clearing site data removes them; download important notes to keep a separate copy. If storage is unavailable, the interface tells you to download your notes.

## Optional: connect stock data and news

Stock information comes from an API: a service the website requests data from. This project supports [Alpha Vantage](https://www.alphavantage.co/documentation/).

1. Obtain your own Alpha Vantage API key.
2. Create an untracked file named `.dev.vars` in this project folder.
3. Add `ALPHA_VANTAGE_API_KEY=your_key_here` to that file.
4. Restart the development server.

The website then requests actual provider data for searches, company details, quotes, historical prices, annual financials, and news. Quote delays, exchange coverage, and endpoint availability depend on your API plan. Some features may need a paid plan. Each uncached company lookup can make up to six requests, so a free plan can be exhausted quickly. Company responses are cached in the running server for ten minutes; searches for an hour. A fresh server may have an empty cache.

Historical charts use up to 100 recent unadjusted daily closes. Stock splits can affect these prices. Selected chart ranges only show dates actually returned by the provider. Quote dates and available chart dates are displayed. Missing figures show a dash, and request limits or unavailable endpoints show an explanation. Failed live requests never silently turn into fictional prices.

## Optional: connect AI summaries

This project supports the [Gemini API](https://ai.google.dev/gemini-api/docs/text-generation).

1. Obtain your own Gemini API key.
2. Add `GEMINI_API_KEY=your_key_here` to `.dev.vars`.
3. Optionally add `GEMINI_MODEL=your_supported_model_name`. The default is `gemini-2.5-flash`.
4. Restart the development server.

Actual AI summaries require both real news from Alpha Vantage and an AI connection. The server sends the provider's article titles and excerpts to Gemini; it does not send your personal notes or claim to read full articles. API usage may have limits or charges. API keys stay on the server and must never be added to browser code or committed to Git.

For a hosted Sites deployment, configure the same key names with Sites runtime environment settings. Local `.dev.vars` files are never uploaded. `.env.example` lists supported settings without containing real credentials.

## Check the project

- `npm run typecheck` — check TypeScript.
- `npm test` or `npm run test:unit` — run all four unit test suites below without calling external services.
- `node tests/finance.mjs` — check the learning content and formula calculations.
- `node tests/research-security.mjs` — check signed-in connected-service access, request size and origin rules.
- `node tests/library.mjs` — check file parsing, permissions, versions and uploaded-data analysis.
- `node tests/backend.mjs` — check demo integrity, missing values, live-data mapping, quota errors, caching, safe API responses, and AI input handling.
- `npm run test:http` — run both HTTP suites against a running local preview. Start the dev server and configure local storage and the preview administrator first; the library suite creates synthetic records and archives them afterward.
- `node tests/library-http.mjs` — check uploads, versions, downloads, private access and admin APIs on a running local preview.
- `node tests/http.mjs` — check the running local website and API routes. Both HTTP scripts accept a local base URL as their first argument; the default is `http://127.0.0.1:5173`.
- `npm run build` — create a production build.

## Project structure

The website uses React, TypeScript, and Next.js-style App Router files through Vinext, with a Cloudflare Worker server. Database access uses Cloudflare D1 and Drizzle; uploads use R2. There is no Supabase dependency.

```text
stock-research-dashboard/
├── app/                     Pages, layout, global styles, and API routes
│   └── api/                 HTTP endpoints; delegate work to services
├── components/              Dashboard, learning, data, and admin interfaces
│   └── ui/                  Existing reusable shadcn UI components
├── hooks/                   Reusable frontend hooks
├── services/                Research, library, and account/access business logic
├── lib/
│   ├── config/              Server environment setting access
│   ├── integrations/
│   │   ├── alpha-vantage/   Stock data and news API client
│   │   ├── gemini/          AI summary API client
│   │   ├── cloudflare/      D1 and R2 storage binding access
│   │   └── sites/           ChatGPT sign-in and Sites connector runtime
│   ├── validation/          Request, upload, and provider-input validation
│   ├── research/            Shared research data, types, and errors
│   ├── library/             Shared file contracts, analysis, and CSV helpers
│   ├── finance/             Learning curriculum and calculator logic
│   └── utils.ts             Shared shadcn styling utility
├── db/                      Drizzle database client and schema definitions
├── drizzle/                 SQL migrations and Drizzle snapshots/journal
├── public/                  Favicon and downloadable import templates
├── docs/                    Architecture and data import guides
├── tests/                   Unit and local HTTP checks
├── scripts/                 Existing build, local setup, and preview tooling
├── worker/                  Cloudflare request entry point
├── vendor/                  Third-party styles and license
├── examples/                Separate D1 starter example, excluded from app checks
├── .openai/hosting.json     Sites identity and storage binding declarations
├── .env.example             Environment variable names and safe examples
└── AGENTS.md                File placement and maintenance instructions
```

The server flow is **frontend → `app/api/` route → `services/` → `lib/integrations/<service>/`**. For example, company research goes through `/api/research`, `services/research.ts`, and the Alpha Vantage client. Summary generation uses the same service and the Gemini client. Library routes call the library services, which validate permissions and input before accessing D1/R2 through the Cloudflare integration. Browser components import shared data and contracts, and use our API routes for server operations.

Put new UI in `components/` and route entry points in `app/`. Keep business rules in `services/`, input checks in `lib/validation/`, and each external connection in its own `lib/integrations/` folder when that service is actually used. Shared code imported by the browser must not read secrets or import server services. The API keys and administrator settings listed in `.env.example` belong in ignored `.dev.vars` locally and Sites runtime secrets when hosted. The `DB` and `BUCKET` names are Cloudflare storage bindings declared in `.openai/hosting.json`, not API keys to put in frontend code.

Keep schema changes in `db/schema.ts` with generated migrations under `drizzle/` (`npm run db:generate`); apply pending local migrations with `npm run setup:data` after building. Keep the existing migration history, snapshots, and binding declarations. No additional tables or generated database types are needed for this organization change. Build output and local runtime data stay ignored.

See [the architecture guide](docs/ARCHITECTURE.md) for the file move map and details of the API/service boundaries. Existing framework configuration and Sites tooling remain in their established locations; this repository organization does not publish a hosted update.

This is a learning and research project. AI can make mistakes. News and price trends are not guaranteed predictions or personalized investment advice.


## Accounts and file permissions

Hosted accounts use ChatGPT sign-in through Sites. The verified site owner is configured privately as the bootstrap administrator. Other admitted visitors begin as users. An administrator can change an existing signed-in user's role; there is no browser switch that grants admin access.

Administrators can manage all company files and publish shared datasets. Ordinary users can read shared datasets and manage their own private files. The server checks access for uploads, details, version links, changes, and downloads. The owner administrator remains protected.

Site sharing and application roles are separate. This update preserves the existing private site audience. Grant another person site access through Sites first; they appear in Administration after signing in. A role change inside the app does not invite someone or make the site public.

Local development uses the supplied preview identity (`local_seedy`), not independent real accounts. Never use that identifier to configure a hosted administrator. Hosted owner settings belong in the `STOCKWISE_ADMIN_EMAILS` or `STOCKWISE_ADMIN_USER_IDS` runtime secret.

Personal notes remain device-local and are now separated by signed-in account. Original unscoped browser notes remain untouched; they are not automatically exposed to a new account.

## Uploads and website sources

CSV/JSON uploads are validated and analyzed. Supported reference attachments are PDF, XLSX and DOCX; this version stores these documents without extracting their contents. The limit is 5 MB per file and 10,000 structured rows. Unknown columns, malformed dates, duplicate dates, invalid numbers, and incompatible previous-version links produce a clear error.

Sources are saved HTTPS website references, not automatic scraping or arbitrary URL imports. Alpha Vantage remains the supported optional API for live provider data and news. Each uploaded dataset records its company, currency, owner, visibility, timestamp and previous version. The data page shows the actual period and assumptions used by its calculations.

Files and parsed data are stored in protected R2 objects; D1 stores users, file metadata and activity. Local preview and hosted storage are separate. Archiving preserves records and can be reversed. Raw files and local database contents are ignored by Git and excluded from deployment source.

Read [the import guide](docs/IMPORT_GUIDE.md) for examples and [the frontend/backend map](docs/ARCHITECTURE.md) to see exactly where each section lives.

If earlier browser-only notes are detected, the dashboard offers an explicit **Import earlier notes** action. Import only data that belongs to you. It preserves existing account notes and leaves the original browser records untouched.
